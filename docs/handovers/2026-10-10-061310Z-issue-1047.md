## First next action — fix lifecycle ownership before native acceptance

Read the specification and the actual host teardown/install/provenance code. **Do not merge or run a real profile upgrade at this checkpoint.** New broker IO joins expose a confirmed deadlock risk, and no fix was applied before handover.

```sh
cd /tmp/te-shared-ai-host

rg -n 'fn retire|fn shutdown|fn install|fn install_path|fn begin_operation|fn relocate_after_rename|fn ensure_mode|fn begin_drain' src-tauri/src/installed_plugins
```

Current `backend::retire` keeps the registry mutex through `broker.stop()` via an if-let temporary; `shutdown` keeps it through the drain iterator. `broker.stop()` now joins retained stdout/writer/stderr workers. A reader can be waiting for that registry or a lifecycle read, producing a deadlock. Callers also invoke retire while holding lifecycle writes: install, uninstall and disable. Merely extracting the registry entry fixes only one of these seams.

Independent review recommends this architecture; it is a proposal, not implemented code:

1. Install a native package-ID mutation fence under a **short** lifecycle write after checking durable claims, CallLeases, startup work and publisher leases. Fence all SDKs and absent/new installs, independently of a Broker phase. Ordinary same-package ensure/admissions must reject until the owner finishes; unrelated packages remain usable.
2. Quiesce, retire, kill/reap and join outside registry, lifecycle and provenance locks. All startup work needs admission ownership before handshake plus a fence check before publishing its broker.
3. Snapshot/copy declared state while the fence excludes writers. Keep the prepared payload/candidate private; do not update installed.json before preflight succeeds.
4. Preflight an explicit Installed payload against an explicit private validation data directory. Deny all candidate reverse execution, credentials, text, artifacts, services and mutation events for SDK1/2/3. Current ensure setup copies real initialDataFiles and registers real consumer roots; candidate setup must skip these and migration scheduling.
5. Legacy SDK2 Trace ignores read-only initialization and writes its DB. Use a private validation copy/capability boundary, and account for stored absolute publication paths; a cloned DB alone is not proof that no external path can change. Validate this using the actual prior package, not a modern mock that already supports readonly flags.
6. Publish the index and durable commit decision after successful private validation. Stop/join a rejected candidate outside locks before restoration. Retain the fence until rollback/index state is durable; activate the committed real-data backend only afterward.
7. Replace provenance lifecycle reads spanning ensure/RPC with package CallLeases selected under a short gate. `begin_operation` must retain its CallLease through publisher Lease insertion to close the accepted-record/lease-registration gap. Preserve the narrow legacy activeRunIds/OWNERSHIP handshake ordering, without holding it over stop, snapshot or restoration.
8. Closing rejects new admissions but must let the existing mutation owner finish commit/rollback (or leave a valid Prepared journal). Shutdown must wait MUTATIONS/fence ownership as well as the queue worker before releasing PROFILE_OWNER; an unlocked mutation is no longer covered by a final lifecycle write.

Required observable fixtures: held preflight leaves another package's controls responsive; candidate reverse requests cause zero dispatch/credential changes; original DB bytes survive failed validation/rollback; SDK1/2 compatibility is genuine; startup cannot surface after fence installation; shutdown waits unfinished mutation ownership.
