# Host integration

TraceExplorer is built and packaged independently. `plugin.json` declares package identity, contributions, exact Svelte ABI, and mutable state files. The release builder adds platform and payload size/SHA256 declarations to `manifest.json` in a `.teplugin` ZIP.

The host loads frontend assets through its restricted `plugin:` protocol. It exposes the SDK runtime with Svelte 5.56.3 public/internal bindings, modal and image-editor components, thumbnails, and a native save picker. The runtime keeps `sdkVersion: 1` for existing plugins and adds `apiVersion: 2` with a `capabilities` list (`fileViews`, `fileViewEligibilityPending` for synchronous reactive eligibility that can hold neutral first paint for up to 400 ms, `previewInfo`, `previewTargets`, `blobWorkers`, `selectionAnchor` for marquee selection that preserves the host cursor and Shift-range anchor, `fileTile` for individual host tiles and grid metrics through `ui/file-tile`, `fileTiles` for whole lists through `ui/file-tiles`, `jobRetry` on hosts that show a Retry action for a failed job whose registration passed `retry`, and `presentation.openImageEditor` (an optional context member, detected by its presence) on hosts that can open the image editor directly in one of the plugin's editor tools and settle when it closes); `plugin.json` declares `sdkVersion: 2`, which only SDK-2 hosts accept.

Two independent capabilities extend AI image dialogs. `paneDialogs` plus a callable `workspace.capturePane` enables synchronous owner capture and `openDialog(id, props, { scope: "pane", pane })`; the host-issued handle is valid only for that pane's lifetime. Failed capture is an action error. Without support, Trace uses the existing two-argument window-modal call. `fileDropTargets` plus a callable `workspace.registerFileDropTarget` enables the Inputs section as a host-routed target. Registration takes `(element, handler, { enabled })` and returns an idempotent disposer; `enabled` is a live predicate, and false consumes the drop without delivery or filesystem transfer. The handler receives ordered local paths and source `"pane"` or `"external"`. Trace never installs a Tauri drag listener or infers paths from DOM files. Either capability works without the other; older hosts retain selected-image inputs and show no drop affordance. Inputs are inspected in chunks of at most eight before being appended, with exact-string duplicate identity; canonical aliases remain subject to backend validation.

Native image-job timing cohorts are an additive feature announced during backend initialization as `jobService: {version: 1, estimateKey: true}`. Detect the `estimateKey` boolean, never the host version. The host reserves the job before Trace prepares its recipe; Trace includes an opaque `estimateKey` in `jobs.status` receipts once that recipe exists, only on supporting hosts. The host pins the first key in its durable `JobRecord` (optional for older records), rejects changed keys, and preserves it if a downgraded consumer omits the field. Keys are `image-v1:` plus a SHA-256 digest of a fixed tuple containing provider package, adapter, model, requested size, resolution, and input bucket (0 versus ≥1); prompts, credentials, input identities and connection revisions are excluded. The ASCII key is 73 bytes, within the host's 128-byte limit. This is a native receipt extension; the frontend SDK registration shape is unchanged.

Job presentation is negotiated independently: runtime capabilities `jobReveal`, `jobCost`, and `fileViewReveal` enable the host's Show image and cost controls. Backend initialization advertises `jobService.revealV1` and `jobService.costV1`; Trace adds optional camelCase `reveal` and `cost` to `jobs.status` and legacy completion events only for the corresponding flag. Reveal is re-read on each status call: saved artifacts point to their current file path; unsaved artifacts point to `trace.view` in their publication folder with `targetId: "artifact:<id>"`. `FileViewContribution.reveal(targetId, pane, signal)` loads and expands the artifact's current component and focuses it for Preview, and rejects missing artifacts. Aborting during loading leaves selection and expansion unchanged.

Trace replies to initialization with `features: ["receiptBillingV1"]`. Hosts advertise `serviceService.receiptBillingV1` to providers, which include optional receipt `billing` only when supported; the host strips billing for consumers without the feature. Receipt version remains 1. Trace validates and replaces `run.details.provider_billing` on each receipt: `cost` is a non-negative decimal string (at most six fractional digits), an ISO currency code, an estimate flag and a source of at most 64 characters. Optional evidence has a schema of at most 64 characters, at most 32 keys of at most 64 characters, and scalar values (strings of at most 128 characters). Trace displays provider costs with exact decimal rounding (`US$0.08`, `≈US$0.08`, `<US$0.01` for a positive sub-cent charge); missing costs have no row. Native OpenAI/Codex paths supply no pricing.

The progress panel labels timing as an **estimate**. It uses the median of the latest 20 successful, valid completions matching `(source, estimateKey)` after at least three samples, then falls back to source history after three samples, then 120 seconds. Jobs past the estimate say “longer than usual”; elapsed time alone never signals completion. Failures, cancellations, unknown outcomes, missing end times, and durations outside 1 second–1 hour are excluded.

SDK 2 adds `registerFileView` (a main Explorer view that receives a pane-scoped `pane` handle: directory, entries, selection, focus, select/open/context menu, and Preview targets), `registerPreviewInfo` (sections appended to Preview info for files or the plugin's own targets; they pad by the host's `--preview-info-inset`, with a 16px fallback for hosts without it, to line up with its info rows), and `workspace.toggleFileView`/`getFileView`. Preview targets are plugin-owned, non-file subjects with explicit actions; they are never draggable paths. The host clears a plugin's views and targets when it is disabled or removed. Trace's layout worker is created from a blob URL, which the host CSP allows (`worker-src 'self' blob:`) and announces through `blobWorkers`; without it, layout runs on the main thread. Plugin contributions receive public workspace, settings, event, job, and backend services; they import no host stores. The TypeScript contract is [plugin-sdk/index.d.ts](plugin-sdk/index.d.ts).

The backend speaks bounded JSON-RPC2 over stdio. Host initialization supplies active publisher leases before reconciliation. Generation uses host job IDs and durable operation IDs; acceptance/status recovery queries never replay a provider request. Codex subprocesses run through the host's owned process service, so backend death cancels them. Large responses are chunked and process output uses bounded, owned spools.

**Owned processes.** `host.process.run` takes `{program, args, cwd, env, stdoutLimit, stderrLimit, stdin?}`, with unknown fields refused; `te_plugin_runtime::process::ProcessRequest` builds exactly that shape. Hosts that accept `stdin` advertise `processStdin: {version: 1, maxBytes}` in `initialize` (256 KiB today). `stdin` is a UTF-8 string of at most `maxBytes` bytes, and the whole frame must fit 1 MiB. The host writes it to the child, then closes stdin; a child that doesn't read it is an ordinary outcome. `stdin` is omitted when absent, because older hosts refuse the field. Pre-spawn refusals have their own codes, each proving nothing ran: `invalid_request`, `capacity_reached`, `not_found`, `permission_denied` and `not_started` (`process::proves_not_started`). After spawn the host reports `interrupted`, and a reused request ID gets `protocol_error`; both mean the program may have run. Older hosts send `service_unavailable` for every pre-spawn refusal, so it stays uncertain. Image Generation's Codex adapter passes `-` as the prompt and sends the task on stdin when the capability is present. Otherwise it keeps the task as the last argument, and on Windows refuses, before spawning and as a definite failure, a command line the launcher would truncate (8191 characters for `codex.cmd` through cmd.exe, 32767 for an executable). The host contract is in tauri-explorer `docs/shared-ai-services-contracts.md`.

Hosts with `textGeneration` also provide `ctx.text.subscribe` for committed configuration revisions and `ctx.text.openSettings` for global language-model settings. Backend initialization advertises `textService: {version: 1}`; `host.text.describe/generate/cancel` use the connection-wide reverse RPC client alongside process calls. Trace loads the authoritative persisted prompt and sends no image credentials or executable path in title requests. The additive `image_prompt_titles_v1` table keys titles by prompt digest, recipe version and the host's non-secret context fingerprint; the old cache remains untouched. `plugin.trace.json.summarizePrompts` owns the preference. A supporting host migrates legacy summary-off and executable preferences natively before reading the destination, without overwriting explicit choices. An absent capability or unavailable transport quietly preserves original prompts.

Core crop and rename call an optional generic provenance service. They remain available without TraceExplorer installed. The plugin records immutable input digests and exact publication evidence; opaque handles contain no caller-supplied database paths. Existing `trace.sqlite` is imported into the package's data directory without deleting the old copy.

Upgrade waits for accepted work and host publishers to settle. The host snapshots declared mutable files, preflights the new backend with recovery deferred, and durably commits activation before external publication-proof cleanup. A failed preflight restores both index and state. The transaction journal records file presence/digests and a terminal phase so interrupted cleanup cannot erase current history. User outputs and data survive removal.

Build the package with `python3 scripts/package-plugin.py`. Native host integration tests must install this actual archive into an isolated profile; frontend mocks alone do not qualify custom-protocol/CSP/runtime behavior.

The original built-in feature work is preserved in Git history and [host PR #991](https://github.com/xnmp/tauri-explorer/pull/991). Source synchronization from the host has been retired; this repository owns the implementation now.

Ctrl+E is registered without a `when` predicate, which the host treats as always available. It uses `workspace.getCurrentDirectory` when present, falling back to the active Trace pane or the first edit input’s folder on older hosts. Edit inputs come from `workspace.getCombinedSelection()` when the host offers it (selected entries across the active tab's panes, focused pane first, deduplicated by path); on older hosts the plugin falls back to the active pane's selection.

The shared image-editor component uses its `initialTool` for that opening. Plugin AI dialogs open directly in their requested tool; core Crop Image… opens the crop surface separately. Commands can declare a default single shortcut or two-step chord (for example `Alt+M P`); the host registers it in Keyboard Shortcuts, preserves user overrides and retires it with the plugin context.

Where the host announces `fileTile`, Trace owns the folder grid and renders each ordinary entry through `ui/file-tile` (`FileTileProps` and `FileTileModule` in [plugin-sdk/index.d.ts](plugin-sdk/index.d.ts)). The module supplies a single `role="gridcell"` and `tileGridMetrics(size?)`: minimum cell width, allocated height, gap and grid padding. Trace owns grid/row roles, path-based selection, roving focus, keyboard navigation, virtualization, stacks, bands and motion. Select/menu callbacks receive the original mouse event; keyboard events are forwarded unchanged. The host owns icons, thumbnails, clipboard styling and pane-bound inline rename. Failed video thumbnails can be retained by path through the optional callback. The capability and module are detected at runtime; older SDK 2 hosts use the plugin’s existing fallback tile markup and styling. `ui/file-tiles` remains an SDK export for other consumers.

The minimum host contract remains plugin SDK 2 with Svelte 5.56.3. `fileTile` improves ordinary tile fidelity and is optional; release notes should state that minimum and the optional capability. Native smoke must install the packaged plugin once against a host with `fileTile`, and once against a host without it. The browser harness simulates both surfaces but does not validate native loading, CSP, or host inline rename.

Plugin styles use only host theme tokens without a fallback ([plugin-sdk/theme-tokens.ts](plugin-sdk/theme-tokens.ts)); `tests/plugins/theme-tokens.test.ts` enforces this.

Hosts with `selectionAnchor` accept `pane.setSelection(paths, null, { keepAnchor: true })`.
Only the listed selected set changes; the range anchor and cursor stay untouched,
including when empty or when the cursor is no longer selected, and `focus` is
ignored. Trace uses it for marquee frames, then records fresh ordered picks.
Without the capability, Trace retains the original `setSelection(paths)` behavior.


Trace folder visibility preloads `trace_folder_candidates` at frontend activation
and reloads on `trace:changed`. This SQL superset includes direct parents of all
artifact/locator paths and contexts for running, uncertain, interrupted and
succeeded runs. It skips recorded-file stats and folder index builds; exact
`folder_has_trace` results still govern known folders. Candidate paths are
persisted canonical paths (dunce-simplified on Windows), compared with the
frontend's `directoryKey` rules. The first candidate answer offers Trace while
an exact lookup checks presence and components; a false positive switches back.

On hosts advertising `fileViewEligibilityPending`, unknown ordinary directories
answer `"pending"` while the queued exact lookup runs. The host holds its neutral
background for up to 400 ms, then falls back to the listing if still unresolved;
a late true answer still switches to Trace. Known answers stay visible during
refresh, and lookup failures settle false. Older hosts receive false instead of
pending. Candidate preload remains an optimistic first-visit optimization.


Canonical directory identity is a separate integration limitation. The current
host's `files/directory_identity.rs` preserves Unix symlink aliases and Windows
short names, while Trace's `folders::key` follows links, and macOS shows `/var`
for `/private/var`. The SQL set is a superset in Trace's **canonical namespace**
only: for `/alias -> /real`, a stored `/real/image.png` yields `/real`. So only
a candidate hit is trusted (an optimistic `true`). A miss answers `"pending"` (false on older hosts) and is
still checked with the exact `folder_has_trace` lookup, which canonicalizes, so
an alias shows Trace once that answer arrives, as before candidates existed. A
Rust regression test documents the canonical-key contract.
